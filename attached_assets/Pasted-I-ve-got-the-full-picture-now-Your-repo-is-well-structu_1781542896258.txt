I've got the full picture now. Your repo is well-structured and the EAS+pnpm+Metro wiring is correct (the AppEntry.shim.js + Metro resolver fix is solid). The failure is almost certainly native, on Skia — and your one commit is literally "Add build properties to include missing header files for Skia," so you already know where the fire is. Here's what I found, in priority order.
1. Your withSkiaFix plugin has a bug that can break the build worse than the problem it fixes.
It appends a brand-new post_install do |installer| block to the Podfile. But an Expo Podfile already has one. In a Podfile, a second top-level post_install block silently overrides Expo's — and Expo's post_install sets deployment targets, New Arch flags, and C++ build settings. Losing it causes exactly the kind of compile failures you're chasing. On top of that, the guard target.name == 'react-native-skia' is an exact match; with useFrameworks: static + Skia 2.4.x the pod target often isn't named exactly that, so your header path may never actually get applied. Net result: it either clobbers Expo's setup or does nothing — and the "missing header" error survives.
The fix is to inject into the existing post_install instead of adding a second one, and match the Skia target loosely.
